\chapter{Building blocks}\label{ch:blocks}
\chapterstatus{draft}{2026-11-16}{\src{src}, \src{CLAUDE.md}, \src{Dockerfile}}

Slotty is one Next.js application and one background worker, built from the same source tree
into the same container image. The code is layered so that business rules can be tested without a
database, and so that every change to data goes through a service that checks who is asking.

\section{Layers}
\begin{xltabular}{\linewidth}{@{}P{30mm} P{38mm} L@{}}
  \toprule
  \thead{Layer} & \thead{Where} & \thead{Responsibility}\\
  \midrule
  \endhead
  Pages and components & \src{src/app}, \src{src/components} & Server-rendered pages (App Router) and client components. Read through services; never write to the database.\\
  Public pages & \src{src/app/page.tsx}, \src{src/components/landing}, \src{src/app/privacy}, \src{src/lib/site.ts} & The landing page for signed-out visitors (signed-in users are redirected home) and the privacy notice. Static content: no service calls besides reading the session. The landing page has its own design, scoped to a \code{data-theme="slotty-landing"} wrapper (\src{src/components/landing/landing.css}; Mona Sans and Martian Mono loaded only there), so nothing reaches the app's theme. Its pictures of the product are HTML, CSS and one small WebGL shader; a few client components play its animations, and without JavaScript or with reduced motion everything shows in its final state (ADR-020). \src{src/lib/site.ts} holds the support address, the institution, the maker credit and the source link.\\
  Server Actions & \src{src/app/actions} & Form and button handlers. Each wraps a service call in \code{run()} (\src{src/server/action-utils.ts}), which refreshes the page and returns \code{{ok, message|error}} to \code{<ActionForm>}.\\
  Services & \src{src/server/services} & One module per area (bookings, slots, evaluations, \dots). Each operation takes an \code{Actor}, checks access itself, enforces rules with \code{assertRule}, writes inside one transaction, and queues notifications and audit entries in that same transaction.\\
  Domain & \src{src/domain} & Pure functions: booking rules, slot generation, evaluation transitions, roster parsing, calendar files. Return a \code{RuleResult} whose message is shown to the user. No I/O.\\
  Infrastructure & \src{src/server}, \src{src/lib} & Database client (\src{src/server/db.ts}), mail and push delivery, sessions and passwords (\src{src/server/auth}), time formatting (\src{src/lib/time.ts}).\\
  Worker & \src{src/jobs/worker.ts} & Delivers the email and push outboxes and runs scheduled jobs (\cref{sec:outbox}), including the hourly usage-data totals and clean-up.\\
  Usage analytics & \src{src/lib/analytics.ts}, \src{src/components/analytics.tsx}, \src{src/app/api/events/route.ts}, \src{src/server/services/analytics.ts}, \code{insights.ts}, \code{feedback.ts} & Browser tracker (page views, Web Vitals, errors, funnel steps), the ingest endpoint, daily totals, the platform team's reports at \route{/platform}, feedback and surveys (\cref{sec:usage-analytics}).\\
  \bottomrule
\end{xltabular}

\begin{brule}{ARCH-1}
  Business rules live in \src{src/domain} as pure functions returning \code{RuleResult}; services
  call them with \code{assertRule}. Pages and actions never query Prisma for mutations.
\end{brule}
\begin{brule}{ARCH-2}
  Every service takes an \code{Actor} and checks access itself, using \code{assertCourseRole},
  \code{assertStaff} or \code{assertAdmin} (\src{src/server/services/access.ts}).
\end{brule}
\begin{brule}{ARCH-3}
  Services throw \code{DomainError} for failures a user should see; anything else is a bug and
  surfaces as a generic error.
\end{brule}

\section{Processes and images}
One \src{Dockerfile} builds every process (\cref{sec:aws-compute}):
\begin{xltabular}{\linewidth}{@{}P{26mm} P{56mm} L@{}}
  \toprule
  \thead{Process} & \thead{Command} & \thead{Notes}\\
  \midrule
  Web & \code{node server.js} & Next.js standalone output: only the files the server traces.\\
  Worker & \code{node dist/jobs/worker.js} & Bundled by Bun at build time; runs on plain Node.\\
  First admin & \code{node dist/jobs/create-admin.js} & One-off; reads \envvar{ADMIN_EMAIL}, \envvar{ADMIN_PASSWORD}, \envvar{ADMIN_NAME}.\\
  Platform access & \code{node dist/jobs/platform-access.js grant|revoke} & One-off; reads \envvar{PLATFORM_EMAIL}, \envvar{PLATFORM_PASSWORD}, \envvar{PLATFORM_NAME} (\cref{sec:ops-platform}).\\
  Migrations & \code{prisma migrate deploy} & Separate \code{migrate} image target carrying the Prisma CLI.\\
  \bottomrule
\end{xltabular}
