\chapter{Building blocks}\label{ch:blocks}
\chapterstatus{draft}{2026-11-16}{\src{src}, \src{CLAUDE.md}, \src{Dockerfile}}

Uniflow is one Next.js application and one background worker, built from the same source tree
into the same container image. The code is layered so that business rules can be tested without a
database, and so that every change to data goes through a service that checks who is asking.

\begin{brule}{ARCH-1}
  Business rules live in \src{src/domain} as pure functions returning \code{RuleResult}; services
  call them with \code{assertRule}. Pages and actions never query Prisma for mutations.
\end{brule}
\begin{brule}{ARCH-2}
  Every service takes an \code{Actor} and checks access itself, using \code{assertCourseRole},
  \code{assertStaff} or \code{assertAdmin} (\src{src/server/services/access.ts}).
\end{brule}
\begin{brule}{ARCH-3}
  Services throw \code{DomainError} for failures a user should see; anything else is a bug and
  surfaces as a generic error.
\end{brule}

\section{Component states: connection and sync}\label{sec:component-states}
Interaction states (hover, focus, pressed, open, invalid, loading, \dots) say how someone is using a
control. Whether the control can work without the server is a second, independent dimension: a
button can be hovered \emph{and} offline. It is built from three parts (\#161, ADR-038; the agreed
design is step~4 on \#160). This is the reference for the screen redesign (\#58).

\paragraph{Connection status} \code{useConnectionStatus()} / \code{useConnection()}
(\src{src/components/connection.tsx}), also set on the page root as
\code{<html data-connection="…">}:
\begin{xltabular}{\linewidth}{@{}P{30mm} L@{}}
  \toprule
  \thead{Status} & \thead{Meaning}\\
  \midrule
  \code{online} & The last request got an answer.\\
  \code{offline} & The browser has had no network for 2\,s. The delay stops flicker during Wi-Fi handoffs; a page that opens without a network counts at once.\\
  \code{unreachable} & The network is up but Uniflow didn't answer a request, or the service worker served this page from its saved copy (captive portal, outage, lie-fi). Shown at once.\\
  \bottomrule
\end{xltabular}
Both clear on the first request that gets an answer (an \code{online} event, or a probe of
\route{/health/live} every 5\,s); the header then refreshes the page.

\paragraph{Offline policy} Every control that acts declares what it needs:
\begin{xltabular}{\linewidth}{@{}P{22mm} P{60mm} L@{}}
  \toprule
  \thead{Policy} & \thead{Used by} & \thead{When not online}\\
  \midrule
  \code{network} & Every \code{SubmitButton}, every \code{Button type="submit"} (the default), attendance, book, cancel, release & \textbf{Offline} state; the action doesn't run and is never queued\\
  \code{local} & Marking fields & Keeps working; shows its sync state\\
  none & Text, read-only cards & Nothing changes\\
  \bottomrule
\end{xltabular}
\code{Button} hands \code{network} buttons to \code{NetworkButton}
(\src{src/components/ui/network-button.tsx}); custom controls use \code{useNetworkGuard()}.

\paragraph{States and words}
\begin{xltabular}{\linewidth}{@{}P{30mm} P{30mm} P{50mm} L@{}}
  \toprule
  \thead{State} & \thead{Where} & \thead{Looks like} & \thead{Words}\\
  \midrule
  \endhead
  Offline & \code{network} controls & Full shape, muted (\code{--offline}), dashed edge, small crossed cloud; \textbf{not} faded to 50\,\% & Tooltip and accessible name: ``Needs a connection''; a tap shows it as a toast\\
  Saved on device & \code{local} rows & Neutral dot & ``Saved on this device''\\
  Syncing & \code{local} rows & Small spinner (still under reduced motion) & ``Syncing''\\
  Synced & \code{local} rows & \code{--success}, for 2\,s, then nothing & ``Saved''\\
  Conflict & \code{local} rows & \code{--warning}; offers both versions & ``Changed elsewhere''\\
  Needs attention & \code{local} rows & Error colour & The server's message\\
  Unconfirmed & A \code{network} action cut off mid-request & \code{--warning} alert (\code{data-state="unconfirmed"}) & ``Couldn't confirm --- check before trying again''\\
  \bottomrule
\end{xltabular}
Unavailable offline (links to pages not on the device) comes with pre-loading (\#162).

\paragraph{Which state wins} (\code{controlState}, \src{src/lib/control-state.ts}, unit-tested):
a business-rule \emph{disabled} first, so a connection is never promised to fix it; then
\emph{pending}; then \emph{offline}; then \emph{invalid}; hover and pressed come from CSS on top.
Focus-visible always shows.

\paragraph{Why} Offline is styled unlike disabled because disabled means ``not allowed'' and offline
means ``allowed once connected''. Offline controls use \code{aria-disabled}, not \code{disabled}, so
they stay focusable and announce why; the click is blocked in code (and also while the browser
reports no network during the 2\,s delay, since nothing can leave the device). Unconfirmed is not an
error because the change may already have happened; calling it one invites a second booking.

\paragraph{The header indicator} \code{ConnectionIndicator}
(\src{src/components/connection-indicator.tsx}), next to the notification bell, replaces any banner:
hidden while online with nothing waiting; ``Offline'' or ``Can't connect'' with a crossed cloud
(tooltip: when the page was made); ``3 waiting'' or a spinner while marks sync; warning colour and a
count when marks need attention or changed elsewhere; a check for 2\,s once all are saved. Tapping
it lists what's waiting, each linking to the student's row. One polite announcement per change.
Counts come from the drafts kept on the device (\src{src/lib/draft-store.ts}), shared across tabs
with a \code{BroadcastChannel}.

\paragraph{Styling hooks} \code{data-offline="blocked"}; \code{data-sync} with
\code{saved-local}, \code{syncing}, \code{synced}, \code{conflict}, \code{error};
\code{data-connection} on \code{<html>}; colour tokens \code{--success}, \code{--warning} and
\code{--offline} (light and dark, \src{src/app/globals.css}). Components are styled from these
attributes, so the redesign restyles them without touching logic.
