\chapter*{Document control}
\addcontentsline{toc}{chapter}{Document control}

This document is the single written description of Uniflow. Where it and the system disagree,
\textbf{the system is right and the document has a defect}: the code in \src{src}, the schema in
\src{prisma/schema.prisma} and the Terraform in \src{infra/aws} are the sources of truth. Each
chapter names the sources it describes, so a reader can check it.

\section*{Chapter status}
Every chapter opens with a badge saying how far to trust it:

\begin{description}
  \item[\statusbadge{complete}] Describes the system as it is, checked against the named sources on the review date.
  \item[\statusbadge{draft}] Correct where it speaks, but incomplete. Gaps are marked \emph{To be written}.
  \item[\statusbadge{stub}] An outline only: the sections it will have and the sources to draw them from.
\end{description}

\section*{Keeping it current}
A change is not done until the chapters it affects are updated in the same pull request
(\cref{sec:doc-maintenance}); \cref{ch:changes} says which chapter covers which area, and
\src{CLAUDE.md} gives coding agents the same rule. Record every
revision in the change log (\cref{app:changelog}).
